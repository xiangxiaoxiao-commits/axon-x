# Axon 知识图谱架构

## 目标

Axon 的图谱不是“把所有名词连起来”的可视化，而是一个可审计、可治理、可安全召回的项目知识系统。任何进入 Agent 上下文的事实和关系，都应该回答三个问题：它来自哪里、为什么可信、用户能否纠正。

## 分层模型

### 1. 原始证据层

会话、代码、任务和 Obsidian 笔记先保存为带来源的 chunk。原文是最终依据；实体和关系只是便于检索的结构化索引。

### 2. 断言层

实体事实以独立 `Assertion` 保存，包含状态、置信度、多来源、获知时间和有效期；旧版 `observations/obsSources` 仅作为兼容投影。临时部署状态、流水线编号、镜像标签等快照信息在写入时过滤，避免把短期状态固化成长期知识。

只有未过期、无直接冲突且处于 `asserted/verified`、置信度不低于 0.65 的断言可以进入 Agent 上下文。系统只保守识别文本骨架相同的显式肯定/否定冲突；冲突双方都保留供审核，但在确认前都不参与召回。

### 3. 关系层

每条有向关系包含：

- `from / label / to`：明确方向的语义三元组；
- `state`：`asserted`、`candidate`、`verified` 或 `rejected`；
- `confidence`：0–1 的证据置信度；
- `sources`：会话、代码、笔记、任务或 MCP 写入来源；
- `evidence`：支持关系的简短依据；
- `inferred`：旧数据兼容字段，候选关系在 UI 中显示为虚线。

只有 `asserted/verified` 且置信度不低于 0.65 的关系可以参与召回扩展。候选关系可以帮助人工探索，但不能污染 Agent 的事实上下文。

### 4. 治理层

人工删除事实、确认/降级/拒绝事实或关系的决定独立存储在 source cache 之外，并在每次组图时重新应用。因此重新建索引不会让已经纠正的错误知识“复活”，GUI 与 MCP 也读取同一治理结果。每次审核写入带时间、目标、前后状态的历史记录，健康度面板可撤销最近一次有效审核，同时保留已撤销的审计事件。

### 5. 召回层

召回由实体结构和原文 chunk 两个通道组成。实体语义/关键词命中用于定位主题，只沿可信的正向关系扩展；原文片段用于提供细节和可核验依据。输出关系时同时携带置信度和 evidence。

## 数据源信任策略

| 来源 | 默认状态 | 默认置信度 | 说明 |
|---|---|---:|---|
| 静态代码解析 | verified | 1.00 | import、包含、调用等确定性结构 |
| Obsidian wikilink | verified | 1.00 | 人工明确建立的链接 |
| 会话/任务蒸馏明确关系 | asserted | 0.65–1.00 | 必须给出文本依据 |
| LLM 弱关联 | candidate | ≤0.60 | 仅用于浏览，不参与事实召回 |
| 人工确认 | verified | 1.00 | 覆盖自动判断并跨重建持久化 |
| 人工拒绝 | rejected | — | 从组图和召回中移除 |
| 导入的知识包 | 保持包内等级 | — | 不重新评定他人已审核的知识 |

这张表由 `graph.RelationTrustForCache` 按缓存的来源（key 前缀 `code:` / `import:`）
落实，而不是一律按同一个默认值写入。静态代码解析读的是语法树、结论可被机器复核，
因此是 `verified`/1.00；会话蒸馏是模型读转写、可能误读，只能是 `asserted`/0.85。
历史缓存由 `graph.MigrateStaleCaches` 在应用启动时补齐等级（含源会话已被清理的孤儿缓存）。

## 不变量

- 不创建悬空关系或自环关系；关系端点通过实体名和别名归一。
- 不为了让图连通而补边。
- 候选、低置信度和被拒绝的关系不参与召回扩展。
- 被排除会话的 observation、关系和原文 chunk 都不能从 MCP 泄漏。
- 同一三元组来自多个来源时累积来源和证据，采用更强审核状态与最高置信度。
- 人工治理优先于自动抽取，且必须在重新索引后仍然成立。

## 质量门槛

知识视图提供健康度面板，持续统计可信/候选/过期/冲突/无来源事实，可信/候选/无来源关系及孤立实体。离线评测使用固定向量语料走生产召回路径，以 Precision@K、Recall、错误扩展率和来源覆盖率作为回归指标；候选关系进入事实扩展会直接导致测试失败。

## 后续成熟化方向

- 引入时间衰减与代码版本锚点，区分稳定规则和容易过期的实现事实。
- 增加治理历史的筛选、批量审核和指定事件回滚；当前支持持久化历史与按时间逆序撤销。
