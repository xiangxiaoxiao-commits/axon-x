# orch —— 一句话派活，先补全规格再执行

一个小命令，把「潦草的一句话」变成「结构化的任务规格」，你确认后它才真正执行，产出还能被打回重跑。

它解决的不是「模型不够聪明」，而是**人写需求时天然会漏信息**：漏约束、漏验收标准、漏涉及哪些文件。模型拿到模糊需求就跑偏，等你读完一大段产出才发现方向错了。

`orch` 在「发给模型之前」插了一步：先把你的话补全成规格，让你 review。

---

## 装

```bash
./install-orch.sh
```

装到 `~/.local/bin/orch`。如果提示不在 PATH 里，按它的提示加一下。

## 配

配模型只需要环境变量（不用配置文件、不用钥匙串）：

```bash
export ORCH_API_KEY=sk-xxxx
export ORCH_BASE_URL=https://api.deepseek.com     # 换你用的
export ORCH_MODEL=deepseek-chat
```

建议写进 `~/.zshrc`。协议默认按 OpenAI 兼容接口走；用 Anthropic 原生接口再加一行 `export ORCH_PROVIDER=anthropic`。

## 用

```bash
orch do "给订单接口加个超时重试"
```

它会：

1. 把你的话补全成 7 个字段的规格（目标 / 背景 / 约束 / 涉及范围 / 验收标准 / 易遗漏点 / 建议步骤）
2. 打印出来让你看，**模型自己脑补的条目会标 `(推断)`**
3. 你按 `y` 执行，`r` 重新补全，`n` 放弃
4. 产出出来后，`y` 采纳；或者直接输入「哪里不对」——它会带着你的反馈重跑一轮

也可以分步走，适合放到脚本里：

```bash
orch new "一句话描述"      # 建任务，拿到 id
orch enrich <id>          # 补全规格
orch show <id>            # 看规格和执行历史
orch run <id>             # 执行（流式输出）
orch accept <id>          # 采纳
orch reject <id> "反馈"    # 打回并重跑
orch list                 # 所有任务
```

## 一个关键设计：最多 3 个并行

同时提交多个任务时，最多 3 个在跑，其余排队。这不是偷懒——不设上限的话一次提十个任务会直接打爆厂商的限流。

## 知识图谱（可选，但强烈建议）

如果你机器上已经有 Axon 的知识图谱，加上这一行，补全时会自动注入项目背景：

```bash
export ORCH_PROJECT=你的项目名
```

效果差别很大。举个例子，同样的输入「排查连接器告警为什么对数据表产品误报」：

- 不接图谱：补全出来的验收标准是「修复后不再误报」这种泛泛的话
- 接了图谱：会直接写出「检查 `metering_invoke_record` 的聚合分组条件」「确认 `owner_inst_id` 到连接器的归属映射」「回归验证另外三类规则码不产生漏报」——因为这些是你项目里真实存在的表名和机制

采纳之后，任务本身的知识点还会**回写**进图谱，下一个同类任务起点更高。

没有图谱也能用，会静默降级成纯描述补全，不会报错。

## 任务存在哪

和 Axon 桌面版共用同一个 SQLite（`~/Library/Application Support/axon/axon.db`），所以在 CLI 里建的任务在桌面版里也能看到，反过来同理。重启不丢，执行到一半崩了也能重试。

## 边界（先说清楚）

- **执行只产出文本**，不会真的改你仓库里的代码、不会跑命令、不会开 PR。它的定位是「给你方案和代码片段，你自己落地」。
- 打回重跑时会把**上一版产出**一起喂给模型（让它知道要改什么），token 消耗会高一些。
- 规格的编辑历史只保留最终确认版，每轮执行会留快照。

## 常见问题

**报 `provider "xxx" 未在配置中找到`**
说明你没设 `ORCH_API_KEY`，它就去读 Axon 桌面版的配置了。要么补上三行环境变量，要么 `ORCH_PROVIDER` 写配置里真实存在的 provider 名（大小写敏感）。

**报 404 / model_not_found**
模型 id 写错了，或者你的账号没有这个模型的权限。`ORCH_MODEL` 换成账号实际能用的。

**补全出来是空规格**
模型没按 JSON 格式返回，`orch` 不会自动重试（省 token）。任务仍然是可编辑状态，可以 `orch new` 重来或直接手写规格。

**想换模型跑**
`orch` 是任务级记录模型的，不同任务可以用不同模型重跑。
