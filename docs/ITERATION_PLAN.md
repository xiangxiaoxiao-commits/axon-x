# 三轮迭代计划 — 聚焦"让 AI 懂业务与代码"

## 北极星(不变的目标)
让 AI 在被使用时**自动懂这个项目的业务背景和代码**——通过**自动注入/补全隐含业务知识**;知识来源是一个**可迭代补全的知识图谱**。其余一切功能服从这个目标,能砍则砍。

## 每轮都要验的三条
1. AI 使用过程中,相关业务背景**确实被自动注入/补全**了(可见、有效)。
2. 知识图谱能表达业务与代码,并且**可以迭代补全**(用得越多越懂)。
3. 方式不限,只要目标达成。

---

## 迭代 1:做减法 + 打通"注入可见"
**目标**:砍掉与核心无关的功能,把界面收敛到核心闭环;让"业务知识被注入"这件事在 UI 上**可见可信**。
- 砍侧边栏:移除 会话/搜索/对话/终端 四个入口(文件留、不 import)。保留:**任务 / 知识 / 设置**(提交工具暂留为辅助或一并弱化,由 PM 定)。
- 任务补全(EnrichTask)和提交(GenerateCommit)时,把"**注入了哪些业务知识 + 来自哪(溯源)**"在结果区明确展示——用户能看到 AI 到底"懂"了什么。
- **验收**:建一个任务/生成一次 commit,能看到注入的业务知识条目及来源;界面只剩核心三入口。

## 迭代 2:让知识图谱"懂代码"
**目标**:知识图谱不只来自历史对话,还能**从代码/仓库**抽取业务实体与关系(懂代码)。
- 从代码抽知识:扫仓库(或改动文件),用模型/静态分析抽出模块、服务、关键函数、依赖关系,并入知识图谱(复用 graph 的 merge/别名归一)。
- 注入升级:任务/提交时,按"当前涉及的代码/文件"更精准召回相关业务知识(HybridRAG 已有,增强 query 用代码符号)。
- **验收**:对一个真实仓库跑一次"从代码建图",图谱里出现代码实体;做任务时能召回到和代码相关的业务知识。

## 迭代 3:让知识图谱"可迭代补全"闭环
**目标**:用得越多越懂——每次任务/对话/提交产生的新认知,能**回写**进知识图谱,持续长大;支持人工确认/修正(保证质量)。
- 回写闭环:任务完成/review 采纳时,把新学到的业务事实/关系**增量合并**进图谱(复用 IndexProject/merge)。
- 人工可管理:知识视图能看/改/删/确认图谱条目(去噪、纠错),别名归一持续生效。
- **验收**:做完几个任务后,知识图谱条目增多且质量可控;同类新任务能自动带出之前沉淀的业务知识,不用重述。

---

## 分工方式(每轮)
- 架构师/PM(主线):定本轮契约、拆任务、审交付、集成、验目标。
- 需要时派:PM(定范围)、研发(并行改不同文件)、测试/评审(验收)。
- 每轮结束:验三条目标 → 打包重装 → commit 存档 → 进下一轮。

## 复用资产
provider(多模型,含 GLM)/ config / secret / **graph(实体/关系/别名/溯源/embedding)** / MatchKnowledge(HybridRAG 注入)/ graphbuild(IndexProject 提炼)/ task(编排)/ store / db。核心引擎都在,主要做"聚焦 + 懂代码 + 可迭代回写"。
