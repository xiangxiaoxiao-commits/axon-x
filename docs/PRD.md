# Axon 产品需求文档 (PRD)

> 事实源为 `docs/BRIEF.md`。本文档在其基础上细化到可开发、可测试的粒度。若与 BRIEF 冲突,以 BRIEF 为准。
> 版本: v1.0 · 面向 Phase 0-6 · 平台: macOS (第一版仅 macOS)

---

## 1. 产品概述

Axon 是一个跑在 macOS 上的**多模型 AI 桌面客户端**,给重度在终端里使用 AI 编码助手的资深工程师用。它把"关掉终端聊天记录就没了"的临时对话,变成可归档、可回看、可跨会话检索的持久资产;并在用户提问前,根据任务类型自动推荐性价比最优的模型和推理档位,顺带估算这次调用大概花多少钱。用户自带各家 API key,直连官方 HTTP 接口,数据全部落在本地 SQLite,最终打包成可安装、可分享的 `.dmg`。

一句话:**把散落在终端里的 AI 对话,收拢成一个能记住你、帮你省钱、装得上传得出去的本地工作台。**

## 2. 用户画像

### 2.1 主用户 —「阿轩」资深后端工程师 (P0,产品为他而造)

- **背景**: 8 年+ 经验,主 Java(Spring Boot)/ 辅 Go,做企业级后端。每天开多个终端会话用 AI CLI 写代码、调 bug、跑自动化脚本。
- **习惯**: 重视工程质量(改代码必编译+测试、向后兼容、日志规范)。同时开多个模型,凭经验手动切换,自己维护过一份 `routing.json` + `codex-task` 脚本来按任务选模型。
- **痛点**: (1) 终端一关历史全丢,想回看上周那次排查过程找不到;(2) 不确定某类任务该用哪个模型最划算,token 花得心里没底;(3) "这个报错我上个月好像遇到过",但记不清关键词搜不出来;(4) 现在这套是命令行脚本,想要一个真正能装、能给同事分享的桌面应用。
- **诉求**: 稳、不丢数据、省心省钱、能"记住"他处理过的东西。愿意自己配 key,不想把代码/对话传给第三方服务。

### 2.2 次要用户 —「阿轩的同事/朋友」(P2,能用起来即可)

- **背景**: 同为开发者,但不一定像阿轩那样折腾脚本。阿轩把打好的 `.dmg` 发给他。
- **诉求**: 拿到安装包能装上、填个 key 就能聊天、不用看文档也大致会用。对"自动选模型""跨会话记忆"这些能感知到价值,但容忍度更高——第一版做到"能用、好装"即可,不为他做额外定制。

## 3. 用户故事 (按四大痛点组织)

### 痛点一:会话归档 (关终端历史就丢)

- US-1.1 作为阿轩,我想让每一句对话即时落盘,以便就算 App 崩溃或断电,重开后记录也一条不少。
- US-1.2 作为阿轩,我想在左侧看到历史会话列表(按时间倒序,带标题),以便快速回到几天前那次排查。
- US-1.3 作为阿轩,我想给会话重命名、删除、搜索标题,以便管理越攒越多的历史。
- US-1.4 作为阿轩,我想把某个会话导出成 Markdown,以便贴到工单或分享给同事。

### 痛点二:按任务自动选模型 (不知道哪个最划算)

- US-2.1 作为阿轩,我想在新建会话时选一个任务类型(日常开发/难题攻坚/后台自动化/龙虾任务),让系统自动填好推荐的模型和推理档位,以便不用每次凭记忆手动切。
- US-2.2 作为阿轩,我想在发送前看到这次调用的预估成本和历史 IQ/耗时参考,以便心里有数、必要时降档省钱。
- US-2.3 作为阿轩,我想一键切换到该任务的"备选模型",以便首选不合适时快速换档。
- US-2.4 作为阿轩,我想系统能根据我输入的内容给出任务类型的初步猜测,以便懒得选的时候有个合理默认。

### 痛点三:跨会话语义记忆 (以前处理过但想不起来)

- US-3.1 作为阿轩,我想在提问时,系统自动从我过去的会话里找出语义相关的片段,以便不用自己回忆关键词。
- US-3.2 作为阿轩,我想清楚看到"这次回答参考了哪几条历史记忆"(可点开溯源),以便判断参考得对不对,而不是被莫名其妙的上下文带偏。
- US-3.3 作为阿轩,我想能开关"记忆注入"并控制注入条数,以便在不需要时保持对话干净、省 token。
- US-3.4 作为阿轩,我想用一句模糊的话(比如"上次那个连接池泄漏")就能召回相关历史,以便"大概有印象但记不清关键词"时也能找到。

### 痛点四:可安装可分享 (要真正的桌面 App)

- US-4.1 作为阿轩,我想把成果打包成 `.dmg`,以便像装普通 Mac 软件一样双击安装。
- US-4.2 作为阿轩,我想把 `.dmg` 发给同事,他右键→打开就能运行(接受 ad-hoc 签名首次提示),以便零门槛分享。
- US-4.3 作为同事,我想第一次打开时有个清晰的引导让我填自己的 API key,以便不看文档也能开始用。

## 5. 验收标准 (可测,测试角色据此设计用例)

### Phase 0

- [ ] 执行 `wails dev`,10 秒内出现 Axon 窗口且无报错日志。
- [ ] 前端调用后端 `Ping`,页面显示后端返回的字符串(如时间戳),证明桥路通。
- [ ] 在项目根执行 `go build ./...` 退出码为 0。
- [ ] 首次启动后,`~/Library/Application Support/axon/` 目录存在。

### Phase 1

- Given 用户发了一条消息并收到回复,When 直接 `kill -9` 进程后重启,Then 该会话及两条消息完整可见,无丢失。
- Given 打开数据库,When 查询 PRAGMA,Then `journal_mode=wal`。
- [ ] 新建/重命名/删除会话后,侧栏列表即时反映变化;删除有二次确认。
- [ ] 会话列表按 `updated_at` 倒序排列。
- [ ] 首条用户消息发送后,会话自动获得非空标题。
- Given 库为旧版本 schema,When 应用启动,Then migration 按版本号执行完毕且不报错,旧数据可读。

### Phase 2

- Given 已在 Keychain 配好有效 key,When 发送消息,Then 助手回复以流式(分块可见)出现,首块 3 秒内到达(网络正常)。
- [ ] 全盘搜索数据库文件与配置文件,不出现明文 API key(key 仅存于 Keychain)。
- [ ] OpenAI-compatible 与 Anthropic 两种 Provider 各能完成一次完整对话。
- Given key 无效,When 发送,Then 界面显示"认证失败"类可读提示,不显示堆栈,后端日志记录 error 带堆栈。
- Given 请求进行中,When 点"停止生成",Then 流式立即停止,已生成部分被保存。
- [ ] 超时时间可配置;超时触发时给出超时提示而非无限等待。

### Phase 3

- [ ] 选择四类任务中任一类,模型与推理档位自动填为 routing.json 中对应首选值。
- Given 选中"难题攻坚"首选,When 查看发送前信息,Then 显示 IQ、预估成本($)、平均耗时,数值与 routing.json 一致。
- [ ] 切到"备选",模型/档位/三项数值同步切换为备选值。
- Given 用户手动改了模型,When 发送,Then 实际调用使用用户手动选的模型(用户覆盖生效)。
- [ ] (P1) 输入一段明显属于某类任务的文本,启发式给出的默认任务类型合理(用固定样例集验证命中率,阈值由测试角色定)。

### Phase 4

- Given 历史里存在一条与"连接池泄漏"语义相关但不含该确切词的会话,When 用户输入"上次那个连接池泄漏",Then 该历史记忆出现在召回结果 top-k 中。
- [ ] 每次发送若开启记忆,界面显示"参考了 N 条记忆",点开能看到每条的来源会话与摘要片段。
- Given 关闭记忆注入,When 发送,Then prompt 中不含任何历史记忆,溯源显示 0 条。
- [ ] 调整 top-k,召回并注入的记忆条数随之变化。
- [ ] 存量会话回填任务可触发并显示进度;完成后旧会话可被召回。
- [ ] 召回质量抽检:用一组预设 query(测试角色维护),期望命中的目标记忆进入 top-k 的比例 ≥ 约定阈值(见 §6)。

### Phase 5

- [ ] 聊天界面正确渲染 Markdown 与代码块(语法高亮),用户/助手消息视觉可区分。
- [ ] 侧栏可切换会话、搜索标题、重命名、删除,操作后 UI 即时更新。
- [ ] 控制条实时显示当前任务/模型/档位/预估成本,可在此切换。
- Given 全新安装无任何 key,When 打开 App,Then 进入引导页要求配置 Provider+key,配好前无法发送。
- [ ] 请求中/失败/空态均有明确视觉反馈(加载指示、错误横幅、空列表占位)。

### Phase 6

- [ ] `wails build` 产出可双击运行的 `Axon.app`。
- [ ] 生成 `.dmg`,拷到另一台未装过的 Mac,右键→打开可正常启动。
- [ ] 干净机器首次启动自动建库,填 key 后可完成一次对话。
- [ ] 重装/覆盖安装后,`~/Library/Application Support/axon/` 内历史数据仍在。
- [ ] App 显示正确的名称、图标、版本号。

## 6. 非功能需求

### 6.1 性能

- **启动速度**: 冷启动到窗口可交互 ≤ 3 秒(已有历史 1000 条会话内);会话列表首屏渲染 ≤ 500ms。
- **流式延迟**: 网络正常下,发送到首个可见 token ≤ 3 秒;流式过程中 UI 无明显卡顿(渲染节流,单帧不阻塞)。
- **落盘**: 单条消息写库+fsync ≤ 50ms,不阻塞输入。
- **语义检索**: top-k(k≤10)召回 ≤ 300ms(历史 1 万条记忆内,本地向量检索)。
- **大历史**: 会话/消息量增长到万级时,列表分页/懒加载,内存占用不随总量线性膨胀。

### 6.2 安全

- API key 仅存 macOS Keychain,数据库、配置文件、日志、导出文件中均无明文 key。
- 日志、界面错误提示不泄露 key、完整请求体等敏感信息。
- 所有用户输入(会话标题、Provider 配置的 base_url 等)做基本校验(长度、URL 格式);SQL 一律参数化查询。
- 仅向用户显式配置的 Provider 端点发起网络请求,不向任何第三方上报对话内容或 key。
- 导出文件路径由系统文件对话框选择,不由用户输入拼接,避免路径穿越。

### 6.3 数据不丢失

- 即时 append-only 落盘 + WAL:关窗、崩溃、断电后,已产生的消息一条不少。
- 流式回复中途中断(停止/报错/崩溃)时,已生成部分被持久化,标记为未完成而非丢弃。
- Schema 迁移向后兼容:先加列后删列,升级不破坏旧数据;迁移失败要能安全回退或提示,不静默损坏库。
- 数据目录独立于 App 包,重装/升级不清空。

### 6.4 跨会话记忆的召回质量 (关键质量指标)

- **召回率**: 对测试角色维护的一组"模糊 query → 期望目标记忆"样例,目标记忆进入 top-k 的比例作为核心指标(建议初始阈值 ≥ 70%,由测试角色随样例集校准)。
- **相关性**: 注入的记忆需与当前问题语义相关;设相似度下限阈值,低于阈值不注入,避免"塞垃圾上下文"污染回答。
- **可解释**: 每条注入记忆可溯源(来自哪个会话、哪段摘要),用户能判断参考是否恰当。
- **可控**: 用户可关闭记忆或调条数;关闭后回答不受历史影响(可对比验证)。
- **不喧宾夺主**: 记忆注入不应显著挤占用户当前问题的上下文预算,需有 token 预算上限。

### 6.5 工程质量 (承接用户偏好)

- 每个 Go 模块改完 `go build ./...` 通过;关键路径(落盘、Provider 调用、检索)有单元测试。
- 异常不吞:业务异常用自定义错误类型,日志用规范级别(关键路径 info,异常 error 带堆栈)。
- 对外/跨层接口向后兼容;改 DTO/接口同步改测试。

## 7. 明确的边界 (第一版不做什么)

为避免范围蔓延,以下明确**不在第一版范围**:

- **不做 Windows / Linux 打包**:仅 macOS `.dmg`。跨平台留待后续。
- **不做多人协作 / 团队共享**:单机单用户,无账号体系、无权限模型。
- **不做云端同步 / 云备份**:数据仅本地 SQLite,不上传、不跨设备同步。
- **不做正式 Apple 公证 (notarization) 与付费签名**:第一版用 ad-hoc 签名,接受"右键→打开"。
- **不自建 / 不托管模型**:只做各家 API 的直连客户端,不部署推理服务(本地 embedding 仅作为接口预留,非第一版交付)。
- **不做插件系统 / 扩展市场**:功能内置,不开放第三方插件。
- **不做移动端**。
- **不做计费/订阅/用量结算系统**:成本只是"发送前参考预估",不接账单、不代扣费。
- **不做联网搜索、工具调用 (function calling / MCP)、多模态图片输入**:第一版聚焦文本对话 + 归档 + 路由 + 记忆四件事。
- **不做团队级审计日志、合规报表**。

> 上述边界如需调整,须回到 BRIEF 层面重新确认,不在开发中临时扩张。
